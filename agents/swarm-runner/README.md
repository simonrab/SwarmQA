# Swarm runner

An HTTP server that runs inside an XCUITest process and drives any app through
`XCUIApplication(bundleIdentifier:)`. It speaks the wire protocol in
[PROTOCOL.md](PROTOCOL.md); the Python client is `swarmqa/driver/runner_client.py`.

There is one iOS UI-test target and one macOS UI-test target. Each contains a
single never-ending test, `SwarmRunnerTests.testRunServer`, that binds
`127.0.0.1:$SWARM_RUNNER_PORT` and serves requests one at a time on the main
thread until `xcodebuild` is killed.

## Layout

| Path | What |
|---|---|
| `SwarmRunner.xcodeproj` | Generated by `gen_project.py` (committed). Schemes `SwarmRunner-iOS`, `SwarmRunner-macOS`. |
| `gen_project.py` | Regenerates the project. Run it after adding or removing a source file. No xcodegen or tuist needed. |
| `Sources/Runner/*.swift` | Shared by both UI-test targets: HTTP server (BSD socket), endpoint handlers, snapshot serialisation, query matching, JSON writer, screenshots. |
| `Sources/Runner/iOS/`, `Sources/Runner/macOS/` | Per-platform bits (`PlatformBridge`): screen geometry, tap vs click, swipe, keys, installed-app check, macOS entitlements. |
| `Sources/HostApp/HostApp.swift` | Stub host app the UI-test targets build against. The runner never launches it. |
| `build.sh`, `run.sh` | Build for testing, then run. |
| `bench_observe.py` | Times `/observe` (stdlib only). |

## Build

```sh
agents/swarm-runner/build.sh            # both platforms
agents/swarm-runner/build.sh ios        # or macos
```

Prints one `XCTESTRUN <platform> <path>` line per platform. Products go to
`$SWARM_RUNNER_DERIVED_DATA`, default `~/.aqa/swarm-runner/DerivedData`, and
build logs to `~/.aqa/swarm-runner/logs/`. The default is outside the repo on
purpose: in a checkout under an iCloud-synced `~/Documents`, File Provider adds
Finder metadata to every build product and `codesign` fails with "resource
fork, Finder information, or similar detritus not allowed".

No signing team is needed: the simulator build is signed ad hoc and the macOS
build uses "Sign to Run Locally" (`CODE_SIGN_IDENTITY=-`). The build uses the
Release configuration (`SWARM_RUNNER_CONFIGURATION` overrides it).

## Run

```sh
agents/swarm-runner/run.sh ios <simulator-udid> [port]   # simulator must be booted
agents/swarm-runner/run.sh macos [port]
```

`run.sh` execs `xcodebuild test-without-building -xctestrun … -only-testing
<bundle>/SwarmRunnerTests/testRunServer` in the foreground. Kill it to stop the
runner. The runner is ready when `GET /health` answers; it also prints
`SWARM_RUNNER_READY port=<port> platform=<ios|macos> protocol=1` on stdout.
The first start on a freshly booted simulator can take a few minutes.

Several runners can share one build: give each simulator its own port.

### Environment

| Variable | Where | Meaning |
|---|---|---|
| `SWARM_RUNNER_PORT` | test process | Port to bind on 127.0.0.1. Default 8765. |
| `TEST_RUNNER_SWARM_RUNNER_PORT` | `xcodebuild` | How the port gets to the test process: `xcodebuild` passes every `TEST_RUNNER_<NAME>` variable to the test runner as `<NAME>`, on the simulator too. `run.sh` sets it from its port argument. |
| `TEST_RUNNER_SWARM_RUNNER_SERIAL_SCREENSHOT=1` | `xcodebuild` | Take `/observe` screenshots on the main thread after the snapshot instead of concurrently (diagnostics only). |
| `SWARM_RUNNER_DERIVED_DATA`, `SWARM_RUNNER_XCTESTRUN`, `SWARM_RUNNER_RESULT_DIR` | `build.sh` / `run.sh` | Build location, explicit `.xctestrun`, result bundle directory. |

Editing the `.xctestrun` (`EnvironmentVariables` under the test target) works
too, but the prefix needs no file edits.

## Benchmark

```sh
python3 agents/swarm-runner/bench_observe.py --port 8765 --bundle-id dev.swarmqa.PlantedBugs -n 50
python3 agents/swarm-runner/bench_observe.py --port 8765 --no-launch --format jpeg
```

Prints p50/p95/max of end-to-end `/observe` calls and exits 1 when p95 is over
`--budget-ms` (300). Each `/observe` response also carries a diagnostic
`X-Swarm-Timing` header (not part of the protocol) with the snapshot,
screenshot-wait, image-encode and JSON times in ms.

`/observe` starts the screenshot on a background thread and takes the
accessibility snapshot on the main thread at the same time, so the call costs
about max(snapshot, screenshot) instead of the sum. The tree is written with a
hand-rolled JSON writer (under 1 ms for ~150 elements). On an iPhone 17
simulator (iOS 26.5, 8 GB M-series Mac): fixture home screen, 124 elements,
PNG p50 112 ms / p95 217 ms; tree only (`"none"`) p50 65 ms.

## Permissions

- **iOS Simulator:** none.
- **macOS:** the Mac must be logged in with the screen **unlocked**; a locked
  console makes every launch fail with "Failed to activate application …
  (current state: Running Background)". The first run of a UI-test runner may
  also ask to allow Xcode's helper to control the computer (Accessibility /
  Automation, or "Enable UI Automation" on recent macOS). Approve it once in
  System Settings > Privacy & Security; on CI hosts, run
  `sudo automationmodetool enable-automationmode-without-authentication`.
- The macOS UI-test runner app is sandboxed by Xcode.
  `Sources/Runner/macOS/SwarmRunnerUITests-macOS.entitlements` adds
  `com.apple.security.network.server` so it may listen on 127.0.0.1; without it
  the bind fails and the test ends at once.
- The macOS runner drives the real desktop: taps are real mouse clicks.

## Behaviour notes and known limitations

- **Tree:** one `snapshot()` of the application element per call. `role` is the
  lower-cased `XCUIElement.ElementType` name (`staticText` becomes `text`).
  `label` falls back to `title` when empty (macOS controls). An empty label or
  identifier becomes `null`; numeric and boolean values become strings (`"1"`/`"0"` for
  switches and checkboxes). System UI outside the app (iOS permission alerts
  from SpringBoard, the macOS menu bar) is not in the tree.
- **Queries** follow `swarmqa.driver.query`: first match in pre-order of the
  snapshot, then a tap at the centre of its frame.
- **Coordinates** are screen points, converted to XCUICoordinate offsets from
  the application element's frame origin. iOS landscape has not been tested.
- **`size`/`scale`:** on iOS `size` is the application frame (the UI-test
  runner app itself runs in a 320x480 compatibility mode, so `UIScreen` in the
  runner is wrong). On macOS it is the main display, and the screenshot is the
  whole main display at backing scale: 2880x1800 PNG is ~8.5 MB and takes
  ~0.5 s, so prefer `"jpeg"` on macOS.
- **JPEG** re-encodes XCTest's PNG with ImageIO. On the iOS simulator it is not
  faster than PNG and barely smaller at full resolution; it helps on large Mac
  displays.
- **`/swipe`:** iOS presses and drags at `distance / duration_s` points per
  second. macOS sends a scroll-wheel event of (to - from) at `from`, which moves
  content the way a trackpad swipe does; a mouse drag would select text instead.
- **`/key`:** modifiers (`cmd`, `ctrl`, `alt`, `shift`) plus the rest pressed as
  a chord with `typeKey`. On iOS, keys without modifiers go through `typeText`
  (`return` is `\n`), and `home` presses the device Home button. Modifier
  chords on iOS need the simulator's hardware keyboard.
- **`/type`** without a query needs a focused text field; otherwise XCTest's
  "no keyboard focus" error comes back as `internal`.
- **`app_state: "crashed"`** means the launched app is no longer running and
  the runner did not terminate it. An app that quits itself (for example
  Cmd-Q through `/key`) also reads as crashed. Crash issues that XCTest reports
  late for an instance that has since been relaunched are ignored.
- **`/launch`** checks the bundle id is installed first (LaunchServices; on iOS
  through `LSApplicationWorkspace`, not public API) and answers `bad_request`
  if not: `XCUIApplication.launch()` on a missing app waits minutes and then
  kills the test runner. Launch waits for the app to idle, which takes 5 to 10
  s on a loaded machine.
- **Errors:** XCTest issues raised during a call are turned into error
  responses instead of test failures: messages mentioning a timeout or idling
  map to `timeout`, "no matches found" to `not_found`, the rest to `internal`.
  Unknown endpoints answer `400 bad_request`.
- **Action latency:** taps, swipes and keys go through XCTest's event synthesis
  and idle wait, typically 0.5 to 2 s each. Only `/observe` has a budget.
- XCTest-internal APIs used: `XCUIScreen.screenshot()` is called from a
  background thread through the Objective-C runtime to overlap it with the
  snapshot. If a future Xcode breaks that, set
  `TEST_RUNNER_SWARM_RUNNER_SERIAL_SCREENSHOT=1`.
